# گزارش آماده‌سازی بتای SafeVault — ۲۰۲۶/۱۱/۱۸

این گزارش تاریخی است؛ نتیجهٔ اصلاحات بازبینی امنیت و طراحی در
[گزارش ۲۰۲۶/۱۱/۱۹](security-fixes-2026-11-19.md) ثبت شده است.

هدف این مرحله، بتای ویندوز و اندروید است؛ iOS طبق انتخاب مالک به بعد موکول شد.
این گزارش تأیید امنیت مستقل یا اعلام آمادگی انتشار عمومی نیست.

۱. **ورود دومرحله‌ای:** تنظیم TOTP، تأیید رمز حساب، کدهای بازیابی یک‌بارمصرف،
مقابله با استفادهٔ مجدد و محدودیت درخواست اضافه شد. صفحهٔ مدیریت Django هم
عامل دوم می‌خواهد و نشست‌های آن در فهرست قابل لغو ثبت می‌شوند.
[جزئیات و بازیابی](two-step-verification.md)

۲. **بازکردن با تأیید دستگاه:** مسیر اختیاری WebAuthn PRF کلید خزانه را با
تأیید محلی دستگاه باز می‌کند. مرورگر، فراهم‌کنندهٔ passkey و دستگاه باید آن
را پشتیبانی کنند. رمز اصلی ذخیره نمی‌شود. این قابلیت ورود حساب با passkey
یا تضمین استفاده از اثر انگشت به‌جای PIN نیست.
[قرارداد و محدودیت‌ها](device-unlock.md)

۳. **پرکردن رمز در مرورگر:** افزونهٔ Chrome/Edge با جفت‌سازی صریح، تأیید هر
بار، تطبیق دقیق HTTPS، توکن کوتاه‌عمر و دسترسی موقت به تب ساخته شد. خروجی
محلی برای مبدأ بتای محلی بسته‌بندی شد. پرکردن در همهٔ اپ‌های اندروید و
انتشار در فروشگاه افزونه‌ها در این مرحله انجام نشده است.
[نصب و استفاده](browser-autofill.md)

۴. **تشخیص بازگشت داده:** تاریخچهٔ محلی نسخه‌ها و اثرانگشت دادهٔ رمزشده اضافه
شد؛ بازگشت برخی داده‌های قبلاً مشاهده‌شده باعث توقف دسترسی می‌شود. این قابلیت
تازگی سراسری داده روی همهٔ دستگاه‌ها یا رفتار صادقانهٔ سرور را تضمین نمی‌کند.
[توضیح دقیق](browser-history.md)

۵. **خزانهٔ بزرگ:** رمزگشایی صفحه‌به‌صفحه اضافه شد و خرابی صفحهٔ بعدی هیچ
رکورد نیمه‌تأییدشده‌ای منتشر نمی‌کند. سقف‌های حافظه و تعداد رکورد حفظ شدند؛
خزانهٔ نامحدود و پردازش کامل خارج از حافظه همچنان پیاده نشده‌اند.

۶. **تعویض اطلاعات اتصال:** مقادیر محلی کلید Django و رمز PostgreSQL با
تاریخچهٔ Git تطابق داشتند. هر دو تعویض شدند و اتصال جدید تأیید شد. اسکریپت
با دفتر بازیابی محافظت‌شده در برابر قطع‌شدن عملیات آماده شد. نشست‌ها و صف
ایمیل reset قدیمی پاک شدند؛ رکوردهای خزانه و کلیدهای رمزگذاری آن تغییر
نکردند. مهاجرت‌های افزایشی accounts روی دیتابیس محلی اعمال شدند. سرویس
Django و mail worker موجود باید با تنظیمات جدید دوباره اجرا شوند. هر محیط
دیگری که هنوز از مقادیر قدیمی استفاده می‌کند باید جداگانه به‌روزرسانی شود.
تاریخچهٔ Git بازنویسی نشده است.

۷. **بسته‌های انتشار:** بستهٔ قابل حمل ویندوز با SHA-256 ساخته شد؛ پشتیبانی
از امضای اختیاری Authenticode اضافه شد، ولی گواهی انتشار ارائه نشده است.
تنظیمات امضای release اندروید اضافه شد و ساخت release بدون کلید متوقف
می‌شود. گردش ساخت GitHub برای ویندوز، افزونه و اندروید آماده است؛ ساخت iOS
در اجرای دستی اختیاری شد. چیزی commit یا push نشده و اجرای جدیدی روی
GitHub آغاز نشده است. APK جدید و امضای تجاری در این محیط ساخته نشده‌اند.

۸. **وابستگی‌ها:** بررسی کامل npm یک مورد مستقیم در picomatch و چهار مورد
وابسته به آن در زنجیرهٔ ابزار توسعه گزارش کرد. نسخهٔ موجود ۴٫۰٫۷ است و در
زمان بررسی نسخهٔ اصلاح‌شده‌ای منتشر نشده بود. Vite و preview صریحاً به
loopback محدود شدند. این وابستگی وارد خروجی استاتیک محصول نمی‌شود، ولی
گزارش کامل npm هنوز سبز نیست و سرور توسعه نباید عمومی شود.
[گزارش آسیب‌پذیری](https://github.com/advisories/GHSA-fc5q-39xc-vjpf)

۹. **موارد باز پیش از اتکا به رمزهای واقعی:** ممیزی توسط فرد یا تیم مستقل؛
تست واقعی Windows Hello و زیست‌سنجی اندروید؛ نصب و تست افزونه روی مرورگر؛
ساخت APK برای دامنهٔ واقعی و تأیید ارتباط دامنه؛ امضای انتشار در صورت نیاز؛
اعتبارسنجی HTTPS، SMTP، مانیتورینگ و بازیابی بکاپ روی میزبان نهایی. ابزار
توسعهٔ این رایانه JDK/Gradle/Android SDK و Docker ندارد. iOS فعلاً خارج از
هدف بتاست. ضعف شناخته‌شدهٔ وابستگی ابزار ساخت تا انتشار اصلاحیه باز است.

۱۰. **نتیجهٔ اعتبارسنجی:** ۱۳۴ آزمون بک‌اند روی PostgreSQL موقت عبور کردند،
شامل رقابت دو اتصال برای مصرف یک کد بازیابی. ۱۲۶ تست فرانت‌اند، lint و build
موفق‌اند. آزمون مرورگر واقعی در Edge بدون پنجره با پروفایل جدا و دیتابیس
بتای موقت انجام شد: ثبت‌نام، Worker/Web Crypto، ذخیرهٔ رمزشده، قفل پس از reload،
تنظیم TOTP، رد ورود بدون عامل دوم، ورود با کد بازیابی و نمای ۳۹۰ پیکسلی
عبور کردند. تابع تزریق افزونه روی فرم HTTPS ساختگی نیز فیلدها را بدون ارسال
فرم پر کرد. این تست جای نصب کامل افزونه یا زیست‌سنجی واقعی را نمی‌گیرد.
۲۸ تست CLI عبور کردند و تست اختیاری MySQL اجرا نشد. وابستگی‌های نصب‌شدهٔ
Python ناسازگاری اعلام نکردند و مدل‌ها با migrationها همگام‌اند.

گردش CI نیز آزمون مرورگر را روی دیتابیس بتای دورریختنی اجرا می‌کند؛ اجرای
آن روی GitHub هنوز انجام نشده است. برای اجرای محلی، ابتدا build را بسازید و
بتای جدا را راه‌اندازی کنید. Playwright را در محیط ابزار تست نصب کرده و
`SAFEVAULT_PLAYWRIGHT` را به مسیر بسته و در صورت استفاده از Edge،
`SAFEVAULT_BROWSER` را به فایل اجرایی مرورگر تنظیم کنید. سپس از ریشه اجرا کنید:

```powershell
node frontend/tests/browser-smoke.mjs
```

برای تعویض مجدد اطلاعات محلی، با Python محیط backend اجرا کنید:

```powershell
backend/.venv/Scripts/python.exe -B deploy/rotate-local-secrets.py
# فقط در صورت قطع‌شدن عملیات قبلی:
backend/.venv/Scripts/python.exe -B deploy/rotate-local-secrets.py --recover
```

فایل بازیابی، در صورت باقی‌ماندن، حاوی اطلاعات حساس است و نباید چاپ، ارسال
یا حذف شود؛ ابتدا دستور recover را اجرا کنید. این ابزار فقط اتصال loopback
همین checkout را می‌پذیرد و برای سرور اصلی طراحی نشده است.
